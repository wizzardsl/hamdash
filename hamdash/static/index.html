    Cards

    Installed cards. Drag one onto the board to place it, or hit Add. Drop new cards into your cards folder and rescan.

      New card from a web page

      Any page that allows being framed: a cluster, a propagation site, a WebSDR, a wiki. It joins the Cards menu like any other card, and you can delete it from there again.

      Card settings

      Every card shows distances your way, so the log, the map and the bearing panel never disagree about how far away somebody is. The theme applies to the board and to every card on it.

      Callsign lookup

      Automatic needs no account: callook and HamDB between them cover US and Canadian callsigns for free. Anywhere else needs an account — a free HamQTH one is enough. QRZ's XML interface is a paid add-on; without it QRZ refuses the session and hamdash shows you exactly what it said. A rejected login is not retried until you save new credentials or press Test, because these services lock an account out after a few failures. LoTW is a QSL confirmation service, not a callsign directory — it has no public lookup, so it can't fill your grid in.

      Logbook sync

      Generate the key at World Radio League under Integrations → Developer API. It is shown once and stored hashed there, so it cannot be read back — keep a copy. One key covers the whole account. Their API takes one contact per request and allows sixty a minute, so hamdash paces a push; a decade of contacts is better handed to their own ADIF import.

      Save credentials before syncing. Pulling never duplicates what you already have — a matching contact is updated with whatever the other log knows, so confirmations land on the QSO they belong to. LoTW uploads must be signed by TQSL, which holds your certificate; a password cannot stand in for it, so "Push to LoTW" hands your log to TQSL if it is installed and tells you what to do if it isn't.

      Sound devices

      Each radio can be given its own audio in and out — the sound card it is wired to, which on a modern rig is usually its own USB interface. Nothing uses it yet; it is what digital-mode cards (a CW decoder, a waterfall tied to one radio) will open when they are built. Devices are remembered by name, so they survive the renumbering Windows does whenever something is plugged in.

      Hamlib

      Only needed for Hamlib radios, where hamdash starts rigctld for the model and port you choose. The list of supported radios comes from Hamlib itself, so it is whatever your version supports rather than a copy here that would go stale. OmniRig radios need none of this: OmniRig owns the port and the rig type, which is why those fields disappear for it.
